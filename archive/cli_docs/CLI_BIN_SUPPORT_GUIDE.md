# 主 CLI 的 BIN 格式支持使用指南

## 概述

主 CLI (`spectrum_cli.py`) 的**任务二（频谱拼接）**现已支持从 `.bin` 文件目录直接加载和处理 IQ 数据。

---

## 🆕 新功能特性

### 数据源选择

任务二现在提供两种数据加载方式：

| 选项 | 数据源 | 适用场景 | 工作流程 |
|------|--------|---------|---------|
| **1** | NPZ 文件（频谱分段） | 已有预计算的功率谱数据 | 逐个加载 → 拼接 |
| **2** | BIN 文件目录（IQ 数据） | SDR 原始采集数据 | 批量读取 → 计算频谱 → 拼接 |

---

## 📝 使用方法

### 启动 CLI

```bash
python spectrum_cli.py
```

### 选择任务二

```
【主菜单】
  1. 任务一：合成干扰功率谱 (30-2500 MHz)
  2. 任务二：拼接频谱分段         ← 选择此项
  3. 任务三：语义参数恢复频谱
  4. 查看使用指南
  5. 退出
```

### 选择数据源：BIN 文件目录

```
➤ 数据源选择
  1. 从 NPZ 文件逐个加载频谱分段（已计算好的功率谱）
  2. 从 BIN 文件目录批量加载 IQ 数据（自动计算频谱并拼接）  ← 选择此项

选择数据源 (1/2) [默认: 1]: 2
```

## 🔧 BIN 文件配置步骤

### 1️⃣ **设置 BIN 文件目录**

```
➤ BIN 文件配置
  文件命名规范: {type}_{freq}MHz_{bw}MHz_{timestamp}.bin
  示例: single_130MHz_204.8MHz_11h14m22s.bin

BIN 文件目录路径 [默认: data/raw_segments]: data/my_bin_files
```

**支持的文件命名格式**：
- `single_130MHz_204.8MHz_11h14m22s.bin` ✅ 标准格式（含时间戳）
- `comb_100MHz_50MHz.bin` ✅ 无时间戳
- `noise_fm_500MHz_20MHz_test.bin` ✅ 自定义后缀

**元数据提取**：
- `jam_type`: 干扰类型（文件名前缀）
- `center_freq_mhz`: 中心频率（单位 MHz）
- `bandwidth_mhz`: 带宽（单位 MHz）

### 2️⃣ **文件匹配模式**

```
文件匹配模式 [默认: *.bin]: *.bin
```

**示例**：
- `*.bin` - 匹配所有 bin 文件
- `single_*.bin` - 只匹配单音干扰
- `*130MHz*.bin` - 只匹配 130 MHz 中心频率

### 3️⃣ **选择数据类型**

```
➤ BIN 数据类型
  1. int16    - 交织 I/Q int16（最常见，默认）
  2. int8     - 交织 I/Q int8
  3. float32  - 交织 I/Q float32
  4. complex64  - 连续复数 float32
  5. complex128 - 连续复数 float64

选择数据类型 (1-5) [默认: 1]: 1
```

**数据格式说明**：

| 类型 | 存储格式 | 字节/样本 | 自动归一化 | 用途 |
|------|---------|----------|-----------|------|
| **int16** | `[I0, Q0, I1, Q1, ...]` | 4 | ✅ → [-1, 1] | SDR 原始数据（最常见） |
| **int8** | `[I0, Q0, I1, Q1, ...]` | 2 | ✅ → [-1, 1] | 低存储需求 |
| **float32** | `[I0, Q0, I1, Q1, ...]` | 8 | ❌ | 预处理数据 |
| **complex64** | `[C0, C1, C2, ...]` | 8 | ❌ | 标准复数（默认推荐） |
| **complex128** | `[C0, C1, C2, ...]` | 16 | ❌ | 高精度场景 |

### 4️⃣ **频谱计算参数**

```
➤ 频谱计算参数（可直接回车使用默认值）
FFT 点数 [默认: 8192]: 8192
窗函数 (hann/hamming/blackman) [默认: hann]: hann
```

**参数说明**：
- **FFT 点数**: 影响频率分辨率（越大越精细，但计算慢）
  - 推荐值：2048, 4096, 8192, 16384
- **窗函数**: 影响频谱泄漏
  - `hann`: 汉宁窗（默认，平衡性能）
  - `hamming`: 汉明窗（边瓣抑制好）
  - `blackman`: 布莱克曼窗（边瓣抑制最好，主瓣宽）

### 5️⃣ **拼接模式**

```
➤ 拼接模式
  1. MAX - 取最大值（适合干扰检测）
  2. MEAN - 简单平均（降低噪声）
  3. WEIGHTED_MEAN - 加权平均（中心权重高）

选择模式 (1/2/3) [默认: 1]: 1

未覆盖区域填充值 (dB) [默认: -180.0]: -180.0
```

## ⚙️ 高级用法

### 自定义 FFT 参数（高分辨率）

```
FFT 点数 [默认: 8192]: 16384    # 更高的频率分辨率
窗函数 [默认: hann]: blackman    # 更好的边瓣抑制
```

**影响**：
- 频率分辨率提高 2 倍
- 计算时间增加约 2 倍
- 适合精细分析干扰信号

### 只处理特定类型文件

```
文件匹配模式 [默认: *.bin]: single_*.bin
```

**用途**：
- 只拼接单音干扰
- 分类分析不同干扰类型

### 加权平均模式（提高中心频段准确度）

```
选择模式 (1/2/3) [默认: 1]: 3
```

**效果**：
- 中心频段权重高（更准确）
- 边缘频段权重低（减少误差）
- 适合重叠区域较多的场景

## 🔍 故障排除

### ❌ 错误：目录不存在

```
⚠️ 目录不存在: data/raw_segments
```

**解决方案**：
1. 检查路径是否正确
2. 确保使用正斜杠 `/` 或反斜杠 `\`（Windows）
3. 使用绝对路径：`C:/Users/admin/data/raw_segments`

### ❌ 错误：未找到匹配文件

```
✗ 错误: 目录 data/raw_segments 中未找到匹配 *.bin 的文件
提示: 请检查目录路径和文件匹配模式
```

**解决方案**：
1. 检查 `.bin` 文件是否在目录中
2. 修改匹配模式（如 `*.BIN`，大小写敏感）
3. 使用 `ls data/raw_segments` 查看文件列表

### ❌ 错误：数据长度非偶数

```
✗ 错误: INT16 IQ 数据长度必须为偶数，当前 12345
```

**解决方案**：
1. 检查 bin 文件完整性（可能传输损坏）
2. 确认数据类型选择正确
3. 文件可能不是标准 IQ 格式

### ❌ 错误：无法从文件名解析元数据

```
⚠️ 警告: 无法从文件名解析元数据（使用默认值）
```

**解决方案**：
- **非致命错误**，但推荐重命名文件为标准格式
- 标准格式：`{type}_{freq}MHz_{bw}MHz_{timestamp}.bin`
- 示例重命名：`data.bin` → `unknown_100MHz_50MHz_test.bin`

## 🎓 最佳实践

### ✅ 推荐做法

1. **使用标准文件命名**
   ```
   {type}_{centerFreq}MHz_{bandwidth}MHz_{timestamp}.bin
   ```

2. **默认使用 int16 数据类型**
   - 最常见的 SDR 输出格式
   - 自动归一化处理

3. **合理选择 FFT 点数**
   - 一般分析：4096 或 8192
   - 精细分析：16384
   - 快速浏览：2048

4. **根据场景选择拼接模式**
   - 干扰检测 → MAX
   - 降噪分析 → MEAN
   - 重叠区域多 → WEIGHTED_MEAN

### ⚠️ 注意事项

1. **文件大小限制**
   - 单个 bin 文件建议 < 1 GB
   - 大文件可能导致内存不足

2. **采样率一致性**
   - 所有文件应使用相同采样率
   - 混合采样率会导致频谱不连续

3. **频段覆盖**
   - 至少需要 2 个分段才能拼接
   - 建议有 10-20% 的重叠区域
