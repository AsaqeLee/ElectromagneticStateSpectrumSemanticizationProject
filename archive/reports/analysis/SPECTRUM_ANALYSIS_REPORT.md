## 🔧 技术原因分析

### 1. **数据源差异 (根本原因)**

| 方面 | 图像 1 (cli_results) | 图像 2 (stitched_30_2500) |
|------|---------------------|------------------------|
| **数据类型** | 合成测试数据 | 真实 IQ 数据 |
| **生成方式** | `spectrum_composer` 软件合成 | 从 `.bin` 文件 FFT 计算 |
| **处理流程** | `compose_spectrum()` → `stitch_segments()` | `load_int16_iq()` → `compute_power_spectrum()` → MAX 聚合 |
| **标注方式** | 标注为 "(MAX)" | 无特殊标注 |

### 2. **功率校准问题**

**图像 1 的异常低功率 (-180 dB) 的可能原因:**

1. **合成数据未校准**: 
   - 噪声底设置为 -120 dB,但拼接后显示为 -180 dB
   - 可能是功率转换公式缺少校准因子

2. **IQ 数据长度问题**:
   - 配置中 `iq_length: 32768`,远小于真实数据
   - 可能导致 FFT 计算的功率谱幅度异常

3. **拼接算法差异**:
   - 图像 1 使用新版 `stitch_segments()` (有 coverage_map)
   - 图像 2 使用旧版直接 MAX 聚合 (无 coverage_map)
   - 两者可能有不同的功率处理逻辑

### 3. **频率覆盖率差异**

**图像 1 的覆盖率统计:**
```
Coverage map min: 0
Coverage map max: 1
Coverage map mean: 1.7e-6 (0.00017%)
```

**解释**: 只有极少数频点被覆盖,大部分区域使用了填充值 `-180.0 dB` (默认 `fill_value`)

**对比**: 图像 2 没有 coverage_map,说明使用了不同的拼接方法,可能是逐段直接聚合,所有频点都有数据。

## 💡 关键发现

### 发现 1: 两张图来自不同的数据源

- **图像 1**: 从 `jammer_config.json` 配置生成的**合成测试数据**
- **图像 2**: 从真实的 **IQ `.bin` 文件**拼接的频谱

### 发现 2: 使用了不同的拼接算法

| 算法 | 文件 | 特征 |
|------|------|------|
| **新版** | `src/signal/stitcher.py` | 有 `coverage_map`,使用 `fill_value=-180.0` |
| **旧版** | `src/pipeline/stitch/stitch_multi.py` | 无 `coverage_map`,直接 MAX 聚合 |

### 发现 3: 合成数据的校准问题

合成数据的配置噪声底为 `-120 dB`,但拼接结果显示为 `-180 dB`,可能存在:
- 功率计算公式错误
- 缺少 IQ 数据的幅度缩放
- FFT 长度与实际数据长度不匹配

## 🎯 结论

### 差异的根本原因

1. **数据源完全不同**: 一个是合成测试数据,一个是真实采集数据
2. **功率校准缺失**: 合成数据在拼接过程中未正确校准功率值
3. **拼接算法版本差异**: 新旧两个版本的拼接函数行为不同
4. **覆盖率问题**: 图像 1 中大部分频点未被覆盖,使用了默认填充值

### 图像 1 (cli_results) 存在的问题

✅ **不是 Bug,而是预期行为**:
- 这是一个**合成的测试数据**,用于测试 CLI 功能
- 配置中的干扰源 (50/500/1000/1500 MHz) 可能在拼接时被过滤或丢失
- 功率值异常低是因为合成数据与真实数据的幅度差异未校准

⚠️ **需要修复的问题**:
- 合成数据的功率校准 (从 -120 dB 变成 -180 dB)
- 拼接后干扰信号丢失 (只剩下两端的 5 个点)
- `coverage_map` 显示几乎无覆盖

### 图像 2 (stitched_30_2500) 的状态

✅ **正常的拼接结果**:
- 从真实 IQ 数据计算的功率谱
- 功率范围合理 (-40 ~ 91 dB)
- 包含丰富的频谱信号
- 这是**期望的正确输出**

## 🔨 建议修复方向

### 1. 修复合成数据的功率校准

**位置**: `src/signal/spectrum_composer.py`

**问题**: 合成的 IQ 数据幅度可能过小,导致功率谱计算结果异常低

**修复建议**:

# 在 compose_spectrum() 中添加幅度缩放
power_db = 10.0 * np.log10(power + POWER_EPS)
# 添加校准偏移
power_db += noise_floor_db + 120.0  # 补偿默认的 -120 dB 差异

**位置**: `src/signal/stitcher.py:115`

**当前设置**: `fill_value=-180.0`

**问题**: 对于合成数据,这个值可能过低

**建议**: 根据输入数据的噪声底动态设置 fill_value

**测试步骤**:
